# Docs Updates

Use this workflow when runtime behavior changes.

1. Update the focused doc that owns the behavior:
   - API -> `docs/api.md`
   - UI -> `docs/ui.md`
   - data model -> `docs/database.md`
   - conceptual framing -> `docs/overview.md`
2. Keep `README.md` short and install-first.
3. Add process/editing guidance to playbooks, not to product docs.
4. Avoid duplicating the same detailed behavior in multiple docs.
5. Verify changed statements against code or tests before committing them.
